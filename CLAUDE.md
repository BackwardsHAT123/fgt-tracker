# FGT Tracker

Entry page and tooling for the PGA Fantasy Golf Tour (FGT), a private fantasy golf league. Owner: Tom (the commissioner). Explain things in plain terms; he is not a web developer.

Keep this file under ~15 KB. Dated entries, review results and feature write-ups go at the END of NOTES-LOG.md, never here.

## What it is

- Landing page: https://fgt-mt.com/ (logo plus two big buttons: Team Picker, 2027 Tracker). Entry page (team picker): https://fgt-mt.com/team-picker.html. Dashboard: https://fgt-mt.com/dashboard.html. Hosted on GitHub Pages (repo https://github.com/BackwardsHAT123/fgt-tracker, public, branch `main`) with the custom domain set in repo Settings > Pages (no CNAME file; HTTPS enforced). Old backwardshat123.github.io/fgt-tracker/... links forward to fgt-mt.com.
- Domains: fgt-mt.com and fgt-mt.net, both registered and managed at Cloudflare (Tom's account). fgt-mt.com DNS: 4 A + 4 AAAA records to GitHub Pages (185.199.108-111.153, 2606:50c0:8000-8003::153) and CNAME www -> backwardshat123.github.io, all "DNS only" (grey cloud; orange breaks GitHub's certificate). Plus TXT `_github-pages-challenge-BackwardsHAT123` (GitHub domain verification and takeover protection; never delete). fgt-mt.net forwards everything to https://fgt-mt.com (same path and query, 301) via a Cloudflare redirect rule; its two placeholder records (A @ 192.0.2.1, CNAME www) are Proxied (orange) on purpose.
- Players enter name, phone, email, team name (address optional) and pick golfers within a 25-point budget. Entry fee $100, paid by Venmo (handle in `site/config.js`).
- Submissions go to a Google Sheet through a Google Apps Script web app.

## Map

- `site/team-picker.html`: the whole entry page (HTML, CSS, JS, no build step). The "More 1-pointers" list is open by default, alphabetical by last name, in 4 columns (3 on tablets, 2 on phones). `site/index.html` is the landing page (`logo-480.jpg` is a 480px copy of the original logo; title and deadline come from `config.js`).
- `site/players.js`: golfer point tiers and page layout (`window.FGT_DATA`). The file you edit most.
- `site/config.js`: `SCRIPT_URL`, `VENMO_HANDLE`, `ENTRY_FEE`, `DEADLINE_TEXT`.
- `apps-script/Code.gs`: server side. Validates, recomputes points, rejects duplicate lineups, appends to the "Entries" tab.
- `apps-script/Golfers.gs`: GENERATED from `site/players.js` by `node tools/build-golfers.js`. Never hand-edit. Tom pastes it into the Apps Script project as a second file.
- Sheet "2027 FGT" (id in the Drive URL Tom gave; the Drive connector could not find it by id) has tabs: Entries (contact info, private), Golfers, Tournaments (golfer prize money per event, filled by me from pgatour.com after each event via `tools/post-results.js` and the token-protected `action:'results'` call in Code.gs), Lineups (one row per golfer per entry), EventScores (one row per event per team), Standings (team and name only, no contact info; feeds the future dashboard), Settings (number of paid teams, set by Tom after entries close), Schedule (2027 events, finish date, purse; loaded by me with `tools/post-results.js` from a JSON file with an `events` list). Menu "FGT" in the Sheet runs setup/refresh, "Email me the unpaid list" (Paid box unticked; to the owner only) and backups ("Back up the Sheet now", "Turn on weekly backups": Tuesday ~3am trigger, dated copies in Drive folder "FGT Sheet backups", newest 12 kept), and beehiiv helpers (beehiiv is on the free Launch plan: no posts by API). The first time an event's results arrive, `saveResults_` emails Tom a weekly recap draft (`buildRecap_`, from the public feed only; once per event via script property `RECAP_SENT:<event>`; menu "Email me the latest weekly recap" resends) to paste into a beehiiv post; menu "Email me new entrants for beehiiv (CSV)" emails Tom a CSV to import himself (nothing is sent to beehiiv). Weekly prizes (rules sheet): $150 to the winning team at a regular event, $200 at The Players and Signature Events, $200 at the FedExCup Playoffs (FedEx St. Jude, BMW; type `playoff`), $300 at Majors plus $100 for 2nd (`PRIZES` in Code.gs, dashboard.html and index.html; teams tied on money share the prizes for the places they occupy). EventScores has a Prize column, Standings a Weekly Winnings column. Each entry gets a confirmation email from the script owner's Gmail (menu: Send me a test confirmation email); Entries column N is a private Paid checkbox. Scoring is money: highest team earnings wins each event outright (tied teams split that event's pot; EventScores "Pot Share" is 1, or 1 divided by the number tied); two events on one weekend are separate events; a season money list pays a number of top teams Tom sets once entries close (about 17-18% of teams).
- `site/sitebar.js` + `site/sitebar.css`: the shared header on all three pages (logo home link, Team Picker, 2027 Tracker, the light/dark toggle; sends a `fgt-theme-change` event). Pages mark themselves with `<body data-page="home|picker|tracker">` and an empty `<div id="sitebar">`.
- Link previews: `og:`/`twitter:` tags on each page with `site/og-image.jpg` (1200x630, logo + title; made with Pillow from the original logo).
- `site/dashboard.html`: public dashboard. Tabs are grouped: Season (Main, Leaderboard, Top Teams, Schedule), Weekly (Weekly Results, Winner List), Teams (Team Performance), Golfers (Times Picked, Past Finishes, Lineup Analysis). Phone rules under `@media (max-width: 600px)`; popups close on Esc, tap elsewhere or scroll. TAH design (pill tabs and buttons, hairline cards, same tokens as team-picker.html) with a light/dark toggle top right (theme on all three pages: saved choice in localStorage `fgt-theme`, else the device setting, else light); Tom's own point-level palette and the tracker's green/purple/blue stay. Loads fast in three steps: the browser's saved copy (localStorage `fgt-dashboard-data`), then the published snapshot `site/data/dashboard.json`, then the live `?view=dashboard` feed from the Apps Script (`dashboardData_` in Code.gs, 2-4 s); each replaces the last only if the data changed. Refresh the snapshot with `node tools/snapshot-dashboard.js` (unsandboxed; refuses to write anything that looks like an email, phone or Entry ID), then commit and push it. "My team" picker under the tabs (localStorage `fgt-my-team`) sets the default team on every tab and marks it with a flag (⚑) in the Leaderboard, Weekly Results and Top Teams. "Next up" line on the Main tab and home page. `?demo=1` shows fake teams from `site/dashboard-demo.js` (made by `tools/make-demo-data.js`); `?demo=pre` previews the entries-still-open state. Only thing left from the Tableau dashboard: Team Performance strokes gained panels (DataGolf); Duplicate Teams dropped.
- `.github/workflows/pages.yml`: deploys `site/` on every push to `main` (Pages source is "GitHub Actions").
- `.github/workflows/weekly-results.yml` + `tools/weekly-update.js`: automatic results. Runs Sun 4pm and Mon 4:44am MT (each a pair of UTC crons; the wrong-season one skips itself), Sun ~6-7pm and ~9-10pm MT, Mon evening; finds FGT events in `data/schedule-2027.json` that finished in the last 3 days, posts each one pgatour.com marks COMPLETED once its past-results money is really there (it often lags: last year's page, no money column, <30 paid, winner $0, or under 70% of purse/refPurse = not ready, retried next run, not a failure) (full field; Zurich halved via "Team event" in notes), saves the snapshot, commits it as fgt-results-bot and runs pages.yml. Needs repo secret `FGT_RESULTS_TOKEN` (same value as the Apps Script property RESULTS_TOKEN; set with `gh secret set ... --body`, since without a terminal it saves an empty value). Manual token test: run the workflow with "check" ticked. Manual run: Actions > Weekly results > Run workflow (optional exact event name). Results summary appears on the run page; GitHub emails Tom if a run fails. Each run also retries any FGT event that finished 2+ days ago with no results in the Sheet, and fails (so Tom gets the email) if one is still missing.
- `tools/fgt-lib.js`: shared code for pull-results, post-results, snapshot-dashboard and weekly-update.
- `data/schedule-2027.json`: the schedule source of truth (event, finish, purse, refPurse, counts, notes, type = regular/signature/players/playoff/major; optional `pgaName` = pgatour.com's full name when `event` is shortened: Cognizant Classic, Arnold Palmer Invitational, Memorial Tournament, FedEx St. Jude). The weekly job matches on `pgaName` and stores results under the short name; the dashboard's `SHORT_NAMES` also shortens older data (Austin). Edit it, then send it with `post-results.js` so the Sheet's Schedule tab matches.
- `README.md`: setup and behavior notes.

## Point values (rules that stand)

- Tiers by final FedExCup rank: 1-10 = 6, 11-35 = 5, 36-60 = 4, 61-80 = 3, 81-100 = 2, everyone else = 1. Any golfer not listed is a 1-pointer via the write-in box.
- No LIV rules, no LIV bump, no special rules for LIV players. Tom: LIV is dead.
- Ranks 1-50: pgatour.com/fedexcup/fedexcup (final season standings; ranks 1-30 follow Tour Championship finish, not season points). Ranks 51+: pgatour.com/fedexcup/fedexcup-fall. In the Fall table the first number after the name is the projected rank; the "official" column lags.
- Layout in `players.js`: column 1 = 6s, 5s, 4s (ranks 36-50); column 2 = 4s (51-60), 3s, 2s; column 3 = featured 1-pointers (Rahm, DeChambeau, Hatton, Reed, then FedEx ranks 101-121), then Korn Ferry top 20 (Blades Brown is a 4-pointer, so 19 names). `more` is a collapsed searchable list.
